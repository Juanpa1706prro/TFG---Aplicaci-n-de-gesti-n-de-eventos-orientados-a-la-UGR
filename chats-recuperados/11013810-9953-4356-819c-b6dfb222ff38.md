**`/u/:userNumber/*` behavior**

- All authenticated app UI lives under `AppShellComponent` with `userNumber` in the URL.
- Navigation uses array form: `['/u', userNumber, 'map']` (documented in `app.paths.ts`).
- `mapGuard` forces the URL `userNumber` to match the logged-in user for **map** and **events/new** (not for **profile** — you can open another user’s profile).
- `accountOwnerGuard` does the same owner check for **account**.

Effective URLs:

- `/u/123/map`
- `/u/123/map/events` (overlay child)
- `/u/123/events/new`
- `/u/123/profile` (any `userNumber`)
- `/u/123/account` (only own number)

## 3. Profile route and loading by `userNumber`

**Files:**

- Route: `app.routes.ts` → `path: 'profile'`
- Component: `g:\JP\TFG\TFG---Aplicaci-n-de-gesti-n-de-eventos-orientados-a-la-UGR\apps\frontend\src\app\features\profile\profile.ts`
- Template: `...\features\profile\profile.html`
- Types: `g:\JP\TFG\TFG---Aplicaci-n-de-gesti-n-de-eventos-orientados-a-la-UGR\apps\frontend\src\app\core\interfaces\user.profile-interface.ts`
- Param helper: `g:\JP\TFG\TFG---Aplicaci-n-de-gesti-n-de-eventos-orientados-a-la-UGR\apps\frontend\src\app\core\utils\route-param.utils.ts`

**Flow:**

1. Read `userNumber` from the route tree with `routeParamFromPath(snapshot, 'userNumber')`, parse as int.
2. If it equals `authService.currentUserValue.userNumber` → `GET {API}/user/profile` → full private view (`viewerIsOwner: true`).
3. Else → `GET {API}/user/public/{userNumber}` → public view.
4. Reactive: `paramMap` → `switchMap` on each navigation.

Profile is a **full-page** route in `shell-content` (not nested under map). No `mapGuard`, so `/u/otherUser/profile` works for viewing others.

## 6. Guards

All under `g:\JP\TFG\TFG---Aplicaci-n-de-gesti-n-de-eventos-orientados-a-la-UGR\apps\frontend\src\app\core\guards\`

| Guard | Role |
|-------|------|
| `auth-guard.ts` | Hydrate session; unauthenticated → `/auth` |
| `guest-guard.ts` | Logged-in on `/auth` → onboarding / select-profile / map |
| `profile-onboarding.guard.ts` | Onboarding only if profile incomplete; else forward |
| `profile-complete.guard.ts` | App routes need complete profile → else onboarding |
| `persona-selected.guard.ts` | Needs persona choice → `/auth/select-profile` |
| `select-persona-page.guard.ts` | Select-profile only when `needsPersonaSelection` |
| `map-guard.ts` | URL `userNumber` must match logged-in user (else own `/map`) |
| `account-owner.guard.ts` | Same owner check for `/account` |
| `can-create-events.guard.ts` | Requires `CREATE_AND_MANAGE_OWN_EVENTS` capability |

All use `authService.waitForHydration()` + `map()` to return `true` or `UrlTree`.

## Adding a new sidebar page — checklist

### A. Full page in shell (like Profile / Account / Create event)

1. **Feature:** `src/app/features//` — standalone component (`selector`, `templateUrl`, `styleUrl`).
2. **Route:** In `app.routes.ts`, child under `u/:userNumber`:
   - Pick guards: typically `authGuard`, `profileCompleteGuard`, `personaSelectedGuard`.
   - Add `mapGuard` if URL must be own user only; `accountOwnerGuard` for owner-only; `canCreateEventsGuard` for privileged actions.
3. **PATHS:** Add constant in `app.paths.ts`.
4. **Sidebar:** New `` in `app-shell.html` with `[routerLink]="['/u', user.userNumber, '']"`, `(click)="closeSidebar()"`, optional `routerLinkActiveOptions`.
5. **Service (if API):** `src/app/core/services/.service.ts` following `EventsService` pattern + interfaces under `core/interfaces/`.
6. **Params:** Use `routeParamFromPath` / `requiredRouteParamFromPath` for `userNumber`.

### B. Overlay on map (like Events list)

1. Register route as **child of `map`** in `app.routes.ts` (sibling of `events`).
2. Ensure parent `map.html` keeps ``.
3. Copy overlay structure from `events-list.html` / `.css` (`fixed`, dim, panel, dialog ARIA).
4. Inject `ShellUiService`: close sidebar on enter; on close navigate to `['/u', userNumber, 'map']` and optionally `openSidebar()`.
5. Sidebar link points to nested path, e.g. `['/u', user.userNumber, 'map', 'your-page']`.

### C. Conditional sidebar item

Mirror `canCreateEvents` in `app-shell.component.ts`: read `user.globalCapabilities` or profile flags, wrap link in `@if`.
